Summarize distinct flood events for the nine-day period June 1–9, 2025. Inputs under `/root/work` are `gage_height_iv.rdb`, a USGS-style tab-separated instantaneous gage-height file, and `nws_gauges.csv`, an NWS-style station threshold export. In the RDB file, skip `#` comments and the field-type line immediately following the column names. `site_no` is a text station ID, `datetime` gives local calendar time, and `00065` is gage height in feet. An empty `00065` is not an observation. Each NWS data row has an additional, unnamed trailing field; ignore it. Match `site_no` to `usgs id` without removing leading zeroes.

Use the maximum observed height for each station on each calendar date. A date is a flood day if its maximum is at least `flood stage` feet. Consecutive flood dates for the same station form one event. A date with no usable observations breaks an event, just as a non-flood date does. For each event, report its inclusive start and end dates, its number of flood days, and the largest observed height on those days.

Write `/root/work/flood_events.json` as a JSON array sorted by `station_id` and then `start_date`, both ascending. Each object must have exactly `station_id`, `start_date`, `end_date`, `duration_days`, and `peak_ft`. Dates use `YYYY-MM-DD`; `duration_days` is an integer and `peak_ft` is a number rounded to two decimal places. Include no objects for stations without events.
